## 1. Introduction

The **THEi HR System** is a **Java EE 8** enterprise web application developed to streamline internal human resource administration. The system provides an administrative portal that supports: (1) employee profile management, (2) training program enrollment management, (3) installment-based fee payment recording, and (4) automated compliance monitoring through scheduled fee-warning generation.

The solution is built using standard Java EE 8 technologies—**Enterprise JavaBeans (EJB) 3.2**, **Java Persistence API (JPA) 2.2**, and **JavaServer Faces (JSF) 2.3**—and is intended for deployment on a Java EE 8–compatible application server (e.g., GlassFish 5).

---

## 2. Business Logic Layer (Enterprise Session Beans)

The business logic layer is implemented using **EJB** to ensure consistent lifecycle handling, scalability, and reliable container services (transactions, scheduling, and pooling).

### 2.1 `CrudServiceBean` — Stateless Session Bean

`CrudServiceBean` functions as the primary service layer for handling database operations. It performs localized **CRUD (Create, Read, Update, Delete)** actions on core entities, including Employees, Training Enrollments, Payment Records, and active Warnings.

This bean is implemented as `@Stateless` because its operations are transactional, independent, and do not require conversational state between client requests. The stateless design also enables efficient instance pooling by the application server, supporting better concurrency and resource utilization in multi-user usage scenarios.

### 2.2 `TimerServiceBean` — Singleton Session Bean

`TimerServiceBean` implements automated administrative compliance checks using the **EJB Timer Service**. The timer periodically scans enrollments to detect outstanding fees as training start dates approach and then generates warning records accordingly.

It is implemented as `@Singleton` (and initialized at startup) to ensure only one timer service instance runs across the application. This avoids duplicate scans and prevents potential race conditions such as repeated warning creation caused by multiple timer instances. Timer-triggered callbacks are managed using standard EJB scheduling and timeout mechanisms.

---

## 3. Transaction Management

This project relies on **Container-Managed Transactions (CMT)**, which are provided by the EJB container and applied to business methods that modify persistent data.

Transactional boundaries are used for all write operations in `CrudServiceBean` (e.g., creating employee records, updating enrollments, inserting payment records, and generating warnings). This ensures that related changes across multiple entities are committed atomically and remain consistent.

**Example (Installment Payment Update):**  
When a user records a partial fee payment, the system must (1) insert a payment ledger entry and (2) update the parent enrollment’s outstanding balance. CMT ensures these changes either complete together or roll back together if an error occurs, preventing inconsistent states such as orphaned payment records or incorrect balances.

## 4. Presentation Layer (JSF Pages and Backing Beans)

The user interface is built using **JSF (Facelets)** and styled with **Bootstrap 5** for a clean layout and improved usability. JSF backing controllers are implemented primarily using `@ViewScoped` and `@RequestScoped` scopes to balance responsiveness and state management.

### 4.1 Authentication

- **`login.xhtml` + `LoginController`**  
  Serves as the system entry point. It validates administrator credentials against a hardcoded credential set (stored as SHA-256 hashes) suitable for the scope of the project.

### 4.2 Dashboard

- **`index.xhtml` + `DashboardController`**  
  Provides a central overview of system status, including live warning records generated by the timer service. It also computes and visualizes time-to-deadline indicators (e.g., days remaining before course cancellation thresholds) to highlight urgent cases.

### 4.3 Employee Management

- **`employees.xhtml` + `EmployeeController`**  
  Supports creation, updating, and removal of employee profiles. It enforces input correctness using Jakarta/Bean Validation constraints (e.g., mandatory fields, HKID formatting rules, email patterns) before invoking the EJB service layer.

### 4.4 Training Enrollment Management

- **`enrollment.xhtml` + `EnrollmentController`**  
  Supports creation of training programs and enrollment linking. The controller coordinates selection of multiple employees and persists their association to a single course using JPA relationship mappings (e.g., many-to-many or an associative enrollment entity).

- **`editEnrollment.xhtml` + `EditEnrollmentController`**  
  Provides a controlled view for updating training schedules and descriptions, reducing the risk of accidental modification to historical or completed records.

### 4.5 Enrollment Detail and Payment Ledger

- **`enrollmentDetail.xhtml` + `EnrollmentDetailController`**  
  Displays a training enrollment detail page, including participant lists, outstanding balances, and historical payment ledger entries. It also supports installment input and triggers transactional updates via the EJB layer.

## 5. System Design (Persistence Model)

The domain model is implemented using JPA entity relationships reflecting core HR and training-payment requirements:

- Employees can participate in multiple training programs.
- Training programs can include multiple employees (via enrollments).
- Each enrollment maintains payment-related state (total fee, paid-to-date, outstanding balance).
- Payment records are stored as historical ledger entries and linked to the corresponding enrollment.
- Warning records are generated automatically when compliance rules detect risk (e.g., unpaid balance near course start date).

## 6. Development Assumptions

To bridge unspecified requirements in the brief, the following assumptions were adopted:

1. **Authentication Scope:** A single administrative account (`hr`) is sufficient for demonstration, rather than implementing full role-based access control (RBAC).
2. **Demonstration-Friendly Scheduling:** Timer intervals were shortened (e.g., seconds instead of real-world days) to allow rapid testing and evaluation of warning generation without manipulating server system time.
3. **Monetary Representation:** All financial values are stored and processed as standard decimal currency values without multi-currency conversion.
4. **Timezone Consistency:** The system assumes the Hong Kong timezone (`Asia/Hong_Kong`) for date rendering and conversion within JSF views to avoid host-dependent display differences.
